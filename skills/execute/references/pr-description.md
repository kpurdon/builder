# PR descriptions

Read the final diff against its actual base. Check affected callers, feature flags, adoption requirements, compatibility, and persisted effects before claiming limited exposure or easy rollback. Apply the shared [quality and evidence standards](../../../references/quality.md).

Follow the repository's format. Explain the problem, changed behavior, and material review concerns with enough context to understand the change without opening links.

- Use a verified before/after example when it clarifies behavior.
- Name affected users, tradeoffs, and dependencies needed to merge or ship. Keep broader plans and delivery status in the project tracker.
- Support consequential claims with inspectable evidence and revision-pinned code links where useful. Summarize relevant validation and material gaps; omit routine CI updates and per-file inventories.
- For specific review concerns, state the question, what to inspect, your assessment, and remaining uncertainty.

Rewrite for the final diff and remove stale explanations. For visible changes, use the shared [visual evidence guidance](../../../references/quality.md#presenting-validation-evidence).

For authorized publication, verify the repository, branch/base, destination, and draft state; update an existing PR when suitable. Check the published description, rendered evidence, and links.
