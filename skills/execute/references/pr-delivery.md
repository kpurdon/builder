# PR delivery

Check the repository’s contribution guide for its PR policy. Default to merge readiness unless the request, repository policy, or acceptance criteria set a different finish line.

Stack dependent PRs, including frontend changes that require an unmerged backend change.

1. Open new PRs as drafts using the [description guidance](pr-description.md).
2. Before marking ready, finish independent review, address blocking findings, and complete the required checks and reviews available in draft.
3. For merge readiness, mark the PR ready and clear any remaining required checks and approvals on the latest head.
4. Leave merging to the user unless explicitly authorized.

Fix confirmed findings and refresh the review and validation affected by the fix.
