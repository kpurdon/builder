# Session operations

Keep work with the current owner through each delivery stage and use the [brief](../../../templates/handoff.md) for an authorized handoff.

A request for a brief authorizes drafting, and an explicit request to launch authorizes creating the session.

## Receiver selection

Continue with the verified owner or a user-selected receiver, and use a new session only for an authorized independent assignment.

Transfer ownership after the former writer stops and the named successor accepts the remaining work, evidence, and authority.

## Ownership and observation

- Use one stable initiative ID and an authoritative local membership inventory with the verified lead and native session identities, using the project record when the integration has no registry.
- Act on recorded members only, and adopt existing sessions only through explicit selection or authorized transfer.
- Reserve the assignment before launch and verify launch, grouping, startup, and delivery independently.
- Reconcile uncertain or partial launches through the original backend and request using its replay contract.
- Let execution owners observe their dependencies through [monitor](../../monitor/SKILL.md).

## Current-state records

- Keep decisions, dependencies, acceptance, and next actions in one local [project record](../../../templates/project.md) that references the member inventory.
- Use external trackers for authorized state changes and durable decisions, keeping coordination messages and session mechanics local.

## Delivery state and blockers

- Read linked evidence against the assigned finish line when resuming, and keep pending gates with the current owner.
- Contact another session only when it can resolve a concrete blocker or needs an assignment change.
- Raise authority or decisions to the user and continue independent work.

## Launch interface

- Use the requested or recorded interface, then the verified origin or configured default for a new initiative.
- Keep broad discovery in a parent workspace, independent implementations in isolated worktrees, and coupled work together.
- Pass known ticket IDs and requested titles through the selected interface when supported.

## Retirement

- Retire only after verified acceptance, cancellation, or accepted transfer, with authority to close the recorded session.
- Preserve evidence and successor obligations, check for active descendants, and verify closure through the recorded backend.
